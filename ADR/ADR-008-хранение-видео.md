# ADR-008. Выбор способа хранения видеомоментов

**Дата:** 9 ноября 2026 г.  
**Статус:** Принято

## Контекст

Видео значительно крупнее статистических записей, передаётся потоково и имеет другой жизненный цикл. Хранение видеобайтов в транзакционной базе ухудшит резервное копирование и масштабирование основной статистики.

## Рассмотренные варианты

1. **BLOB в PostgreSQL.** Видео хранится рядом с метаданными.
2. **Локальная файловая система сервера.**
3. **S3-совместимое объектное хранилище.**
4. **Только ссылки на внешние видеоплатформы.**

## Решение

Хранить видеобайты в **S3-совместимом объектном хранилище**. Для локальной разработки допускается MinIO, для промышленной среды — совместимый управляемый или самостоятельно размещённый сервис.

PostgreSQL хранит идентификатор объекта, матч, временной интервал, автора, статус обработки, контрольную сумму, длительность, тип содержимого и права доступа. Загрузка и просмотр выполняются по короткоживущим подписанным URL.

## Обоснование

- объектное хранилище предназначено для больших неизменяемых файлов;
- статистика и видео масштабируются независимо;
- правила жизненного цикла позволяют переносить старые материалы в более дешёвый класс хранения;
- подписанные URL не пропускают поток через основной API без необходимости;
- локальный S3-совместимый сервис сохраняет одинаковый контракт сред.

## Ограничения и недостатки

- база и объектное хранилище не участвуют в общей ACID-транзакции;
- возможны незавершённые загрузки и объекты без метаданных, поэтому нужна периодическая очистка;
- доступ к подписанной ссылке действует до её истечения;
- транскодирование, превью и антивирусная проверка выполняются асинхронно;
- функции конкретного поставщика, выходящие за S3-контракт, требуют отдельного решения.

## Последствия

- загрузка состоит из создания намерения, передачи объекта, проверки контрольной суммы и подтверждения метаданных;
- пользователь не видит видео до успешной проверки и обработки;
- резервное копирование метаданных и политика сохранности объектов согласуются отдельно;
- политика хранения может удалить объект только после истечения установленного срока и проверки связей;
- сбой видео не останавливает статистику и онлайн-табло.

## Условия пересмотра

Решение пересматривается, если правообладатели требуют использовать только внешнюю видеоплатформу либо объём медиа не оправдывает собственное объектное хранилище.
