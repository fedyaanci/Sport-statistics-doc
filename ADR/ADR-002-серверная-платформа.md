# ADR-002. Выбор технологии серверной части

**Дата:** 9 ноября 2026 г.  
**Статус:** Принято

## Контекст

Серверная часть должна предоставлять HTTP API, принимать live-события, выполнять фоновые операции, проверять права доступа и поддерживать постоянные соединения с веб-клиентами. Важны статическая типизация, развитые средства тестирования и длительная поддержка платформы.

## Рассмотренные варианты

1. **C# и ASP.NET Core на .NET 10 LTS.**
2. **Java и Spring Boot.**
3. **TypeScript и NestJS на Node.js.**
4. **Python и FastAPI.**

## Решение

Использовать **C# и ASP.NET Core на .NET 10 LTS**. ORM — Entity Framework Core, фоновые процессы — стандартные hosted services либо отдельные worker-процессы. Следует устанавливать актуальные патч-версии .NET 10.

## Обоснование

- ASP.NET Core поддерживает HTTP API, фоновые службы и SignalR в одном технологическом стеке;
- строгая типизация снижает риск несовместимости доменных моделей и интеграционных контрактов;
- встроенный контейнер зависимостей, конфигурация, журналирование и middleware уменьшают количество инфраструктурного кода;
- .NET 10 является LTS-выпуском с активной поддержкой до ноября 2028 года;
- асинхронная модель подходит для большого количества операций ввода-вывода.

## Ограничения и недостатки

- команда должна владеть C#, async/await, EF Core и диагностикой управляемой памяти;
- тяжёлые вычисления прогнозной модели могут быть удобнее в Python и при необходимости выносятся за контракт;
- неправильное использование ORM приводит к избыточным запросам и не отменяет знание SQL;
- обновление на актуальные патчи обязательно; выбор LTS не означает отсутствие сопровождения;
- серверная платформа не определяет архитектурные границы — их требуется обеспечивать структурой решения и тестами.

## Последствия

- серверные проекты используют единую версию SDK, закреплённую в конфигурации репозитория;
- API описывается через OpenAPI;
- обработчики ввода-вывода должны быть асинхронными и принимать токен отмены;
- специфичная для платформы логика не должна попадать в доменное ядро;
- библиотека прогнозирования на другом языке может подключаться как отдельный компонент через версионируемый контракт.

## Условия пересмотра

Решение пересматривается при отсутствии необходимой компетенции команды, завершении поддержки .NET 10 либо доказанном несоответствии требованиям производительности.
