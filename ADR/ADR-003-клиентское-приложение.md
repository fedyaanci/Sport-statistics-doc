# ADR-003. Выбор технологии клиентского приложения

**Дата:** 9 ноября 2026 г.  
**Статус:** Принято

## Контекст

Пользователям нужны интерактивные таблицы, фильтры, сравнения, графики, онлайн-обновления и адаптивный интерфейс. Веб-клиент должен работать на настольных и мобильных устройствах без установки отдельного приложения.

## Рассмотренные варианты

1. **React и TypeScript.**
2. **Vue и TypeScript.**
3. **Angular.**
4. **Blazor WebAssembly.**
5. **Отдельные нативные приложения.**

## Решение

Использовать **React с TypeScript** для одностраничного веб-приложения. Версии зависимостей закрепляются lock-файлом. Серверные данные загружаются через выделенный слой запросов; live-изменения поступают через SignalR.

## Обоснование

- компонентная модель подходит для повторного использования таблиц, графиков и карточек;
- TypeScript позволяет типизировать DTO и события реального времени;
- развитая экосистема визуализации и тестирования;
- адаптивный веб-интерфейс покрывает требование работы на разных устройствах;
- React не связывает серверную часть с конкретной технологией UI.

## Ограничения и недостатки

- одностраничное приложение требует JavaScript и первоначально загружает клиентский пакет;
- состояние кеша запросов и live-события могут конфликтовать без единой стратегии обновления;
- доступность интерфейса и адаптивность не обеспечиваются самим React;
- частое бесконтрольное добавление библиотек увеличивает размер сборки и риски цепочки поставок;
- поисковая индексация публичных страниц слабее, чем при серверном рендеринге. Для текущих сценариев это допустимо.

## Последствия

- бизнес-правила остаются на сервере; клиент отвечает за представление и предварительную проверку ввода;
- API-типы по возможности генерируются из OpenAPI;
- общий UI-набор содержит таблицы, фильтры, уведомления и состояния загрузки;
- сборка проверяет типы, форматирование, модульные и компонентные тесты;
- при появлении требования SEO публичные страницы могут получить серверный рендеринг по отдельной ADR.

## Условия пересмотра

Решение пересматривается, если обязательными становятся полноценная офлайн-работа, платформенные мобильные функции либо поисковая индексация большей части интерфейса.
