# C4-диаграммы системы «Спортивная статистика»

Пакет содержит три уровня модели C4, выполненные в формате diagrams-as-code на PlantUML.

| Уровень | Документ | Исходный код | Назначение |
|---|---|---|---|
| C4 Level 1 | [Контекст](Контекст.md) | [Контекст.puml](Контекст.puml) | Пользователи, система и внешние системы |
| C4 Level 2 | [Контейнеры](Контейнеры.md) | [Контейнеры.puml](Контейнеры.puml) | Исполняемые приложения, хранилища и протоколы |
| C4 Level 3 | [Компоненты](Компоненты.md) | [Компоненты.puml](Компоненты.puml) | Внутреннее устройство Backend API и Live Gateway |

## Согласованность с ADR

| Решение | Отражение на диаграммах |
|---|---|
| ADR-001: модульный монолит | Доменные модули показаны компонентами одного Backend API; фоновые обработчики остаются частью общей поставки |
| ADR-002: ASP.NET Core и .NET 10 | Backend API и Worker используют выбранную серверную платформу |
| ADR-003: React и TypeScript | Веб-приложение показано отдельным клиентским контейнером |
| ADR-004: PostgreSQL | Основная база является источником истины и разделяется схемами модулей |
| ADR-005: RabbitMQ и Outbox | Показаны брокер, Outbox, издатель и идемпотентные обработчики |
| ADR-006: SignalR | Live Hub доставляет обновления по WSS/SignalR |
| ADR-007: Redis | Redis используется только как кеш и backplane, но не как источник истины |
| ADR-008: S3-хранилище | Видео и сформированные файлы вынесены из PostgreSQL |
| ADR-009: OIDC и RBAC | Внешний поставщик идентификации и серверная проверка политик показаны явно |
| ADR-010: автоматическое тестирование | Структурные границы контейнеров и компонентов являются объектом архитектурных и контрактных тестов |

## Генерация изображений

Файлы `.puml` используют C4-PlantUML и набор технологических иконок. Для локальной генерации требуются PlantUML и Java 17 или новее. В Visual Studio Code можно использовать расширение PlantUML; исходный код остаётся главным артефактом, а PNG генерируется из него.
