# Словарь: единый язык проекта

Термины применяются в требованиях, обсуждении, интерфейсе и будущем коде с одинаковым смыслом. Если удобное разговорное слово неоднозначно, используется полное название. Английские эквиваленты ниже помогают именовать сущности, но не задают окончательную схему БД.

Подход к общему языку опирается на [Ubiquitous Language](https://martinfowler.com/bliki/UbiquitousLanguage.html): язык уточняется вместе с пониманием предметной области. Определения ниже относятся именно к данному спортивному проекту.

## 1. Участники и доступ

| Термин | Определение и граница смысла |
|---|---|
| Пользователь | Человек, использующий сервис. В защищённых операциях действует через учётную запись и сеанс |
| Гость | Посетитель без действующего сеанса. Может читать только явно публичные сведения |
| Учётная запись / Account | Идентичность для входа: идентификатор, почта, хеш пароля, состояние подтверждения. Не является спортивной карточкой игрока |
| Сеанс / Session | Ограниченный по времени доступ после успешного входа. Может быть закрыт или отозван без удаления аккаунта |
| Аутентификация | Проверка того, кто обращается к сервису; успешный вход открывает сеанс |
| Авторизация | Проверка, разрешено ли этому участнику конкретное действие над объектом. Не синоним входа |
| Роль | Вид выполняемой работы: например, оператор или организатор. Одной роли без области недостаточно для права на любой матч |
| Область доступа / Scope | Турнир, команда, матч или другой согласованный набор объектов, в пределах которого действует назначение |
| Назначение доступа | Сохраняемая связь аккаунта, роли и области с состоянием действия/отзыва |
| Заявка доступа | Просьба выдать роль в области. Состояние ожидания решения не предоставляет права |
| Администратор | Уполномоченный участник, который назначает/отзывает доступ и связывает аккаунт с игроком |
| Привязка профиля | Проверенная связь аккаунта со спортивным профилем игрока. Не назначает права оператора |
| Запрос сброса пароля | Сохраняемый одноразовый запрос с ограниченным сроком; его успешное использование меняет пароль |
| Почтовое отправление | Локальная запись о назначении письма, попытках и результате передачи почтовому сервису |
| SMTP | Протокол взаимодействия с внешним почтовым сервисом. Принятие письма этим сервисом не доказывает доставку адресату |

## 2. Соревнование и участники

| Термин | Определение и граница смысла |
|---|---|
| Вид спорта | Набор спортивных понятий и действий, для которых определены правила и метрики |
| Регламент / Ruleset | Версия правил допуска, действий, позиций, составов и расчётов, применяемая к сезону |
| Турнир / Tournament | Соревнование как длительно существующая организация спортивного цикла; может содержать несколько сезонов |
| Сезон / Season | Ограниченный период турнира со своими участниками, матчами и статусом открытости |
| Команда / Team | Спортивный участник, объединяющий игроков. Допуск в один сезон не означает допуск во все сезоны |
| Игрок / Player | Устойчивый спортивный профиль человека. Сохраняет идентификатор при смене команды и не требует отдельного аккаунта для каждого сезона |
| Сезонная заявка команды / Season Entry | Сохраняемый допуск команды и её игроков к определённому сезону. Используется каноническое название, а не неоднозначное «состав сезона» |
| Допуск | Положительное решение уполномоченного участника о возможности участия в конкретном сезоне |
| Матч / Match | Игра двух разных команд в сезоне с расписанием, составами, историей действий и состоянием проведения |
| Состав матча / Match Roster | Версия выбранных игроков и ролей конкретной команды на конкретный матч. Уже сезонной заявки и требует своего подтверждения |
| Организатор | Участник, отвечающий за сезон, расписание, допуск, согласование составов и подтверждение результата |
| Тренер | Представитель команды, который представляет состав, анализирует показатели и подготавливает отчёт |
| Оператор | Участник с правом вести данные назначенного матча; не получает автоматически права на остальные матчи |

## 3. Ход игры, версии и показатели

| Термин | Определение и граница смысла |
|---|---|
| Игровое время | Время внутри спортивного матча по его регламенту. Отличается от календарной даты и времени сервера |
| Игровое действие / Game Action | Принятый спортивный факт с типом, участниками и игровым временем. Попытка неверного ввода ещё не является принятым действием |
| Исправление действия | Сохранение новой редакции принятого факта с причиной и историей. Отличается от повторной отправки исправленных полей непринятого ввода |
| Отмена действия | Сохранение признака, что принятый факт не должен участвовать в расчёте; запись и причина остаются в истории |
| Замена | Событие изменения участия игроков по правилам спорта; закрывает один интервал участия и открывает другой |
| Интервал участия | Отрезок игрового времени, в течение которого игрок участвует в матче |
| Интервал позиции | Отрезок участия на конкретной позиции; смена позиции создаёт новую границу, а не переписывает весь матч |
| Метрика / Показатель | Значение с определёнными формулой, единицей, правилами выборки, округления и версией |
| Статистика | Совокупность метрик, рассчитанных по заданной выборке принятых действий и участия |
| Выборка | Набор данных по согласованным условиям: спорт, период, команда, игрок, позиция и версия источника |
| Нет наблюдений | Для расчёта нет нужных исходных данных. Не равно измеренному числовому нулю |
| Протокол матча / Match Protocol | Сохраняемый документ показателей и действий матча, имеющий редакции и правила публикации |
| Редакция / Version | Идентифицируемый сохранённый вариант объекта. Подтверждение одной редакции не подтверждает будущие правки |
| Предварительный протокол | Редакция по текущим принятым данным до официального утверждения; используется при наблюдении игры |
| Итоговый протокол | Сохранённая редакция после завершения матча, предназначенная для проверки организатором |
| Подтверждение результата | Решение организатора о допустимости конкретной итоговой редакции. Отличается от завершения игры |
| Официальный протокол | Подтверждённая и опубликованная редакция, являющаяся источником официальной статистики |
| Официальная корректировка | Разрешённая процедура исправления опубликованного результата с сохранением основания и новой проверкой |
| Публикация табло / Scoreboard Publication | Сохраняемая настройка доступа зрителей к текущим показателям матча. Обновление экрана не создаёт её снова |
| Момент обновления | Время и версия последних полученных экраном данных, позволяющие заметить устаревший показ |

## 4. Материалы, импорт и история

| Термин | Определение и граница смысла |
|---|---|
| Материал | Общее название отчёта, обзора, инфографики или прогноза; не новый самостоятельный тип вместо этих объектов |
| Черновик / Draft | Уже сохраняемый объект с идентификатором, автором и параметрами/текстом. Не просто открытая форма |
| Готовый результат / Ready | У материала есть сохранённое читаемое содержимое или файл, пригодный для предпросмотра и публикации |
| Публикация материала | Разрешение читать конкретную сохранённую редакцию в сервисе. Не означает автоматическую отправку наружу |
| Отчёт / Report | Сохраняемый материал по сезону с параметрами, версией данных и сформированным файлом |
| Обзор / Review | Редакционный текст о матче со ссылками на использованные спортивные факты |
| Инфографика / Infographic | Сохраняемый визуальный материал команды с параметрами, выбранными фактами и изображением |
| Прогноз / Forecast | Оценка будущего матча по доступным на выбранный момент данным; не гарантированный исход и не запись фактического результата |
| Срез данных / Data Cutoff | Граница доступности сведений, использованных в расчёте прогноза или материала |
| Попытка обработки / Attempt | Сохраняемый отдельный запуск подготовки результата у существующего материала. Повтор не обязан создавать новый материал |
| Ошибка / Failed | Обработка существующего объекта не завершилась успешно; причина сохраняется для диагностики и разрешённого повтора |
| Отказ / Rejected | Принято решение не выполнять расчёт при неподходящих исходных условиях; в прогнозе сохраняется причина недостатка данных |
| Видео / Video | Сохраняемая запись с исходным файлом, обработанным результатом, длительностью и статусом готовности |
| Видеомомент / Video Moment | Связь границ фрагмента готового видео с конкретным действием того же матча |
| Пакет импорта / Import Package | Сохранённые данные внешнего источника вместе с идентификатором, результатом проверки и сопоставлениями |
| Сопоставление источника | Соответствие внешнего идентификатора локальному игроку/команде; само по себе не добавляет гол |
| Конфликт импорта | Пакет нельзя однозначно или допустимо применить; до исправления и повторной проверки матч не изменяется |
| Архивный набор / Archive Dataset | Проверенная историческая копия данных закрытого сезона с перечнем содержимого и ссылками |
| Рабочая копия архива | Восстановленная копия для разрешённой работы; исходный архив сохраняется |
| Резервная копия / Backup | Копия БД и согласованных файлов для восстановления после сбоя. Имеет другой смысл и режим, чем архив сезона |

## 5. Термины требований и моделей

| Термин | Определение |
|---|---|
| Архитектурный фактор / Driver | Требование, ограничение или принцип, заметно влияющий на устройство системы и выбор компромиссов |
| Функциональное требование | Что система должна позволять сделать или получить, например зарегистрировать действие или сравнить команды |
| Нефункциональное требование | Какое качество требуется при конкретных условиях: время ответа, точность, доступность, восстановление |
| Ограничение | Заданная граница допустимого решения: например, навыки Python/SQL и объём учебной реализации |
| Принцип | Правило принятия решений, например сохранение происхождения результата и предпочтение простого решения |
| Агрегат / Aggregate | Граница согласованного изменения данных и защиты правил. Не синоним всей базы, отдельной таблицы или микросервиса |
| Ограниченный контекст / Bounded Context | Область, где термины и модель имеют однозначный согласованный смысл. Белый фрейм доски сам по себе не устанавливает эту границу |
| Команда / Command | Намерение изменить состояние. Может быть отклонена; её отправка ещё не означает успех |
| Запрос / Query | Получение данных без изменения бизнес-состояния. Технический лог чтения не превращает его в команду изменения счёта |
| Доменное событие / Domain Event | Значимый произошедший факт предметной области. На этой доске изменяющие сценарии связаны с сохраняемым результатом; это не общее требование записывать любую внешнюю новость в БД |
| Политика / Policy | Автоматическая реакция на факт либо срок, инициирующая предусмотренное действие |
| View в Event Storming | Экран, форма, таблица или график, с которыми работает человек |
| Модель чтения / Read Model | Сведения, подготовленные для запроса или экрана. View показывает эти данные; они могут получаться обычным SQL-запросом |
| Django view | Обработчик веб-запроса в выбранном фреймворке. Название не тождественно зелёному View-экрану из ES |
| Идемпотентность | Повтор команды с одним ключом и теми же параметрами не создаёт дополнительного эффекта |
| Атомарность | Связанные изменения фиксируются совместно либо не фиксируются; подтверждённого частичного результата нет |
| p95 | Значение, которое не превышают 95% измеренных длительностей в заданных условиях; не максимальная задержка каждого запроса |
| SLO | Целевой уровень качества обслуживания за заданный период, например 99% доступности за 30 суток |
| RPO | Максимально допустимая потеря данных по времени относительно сбоя. RPO 24 ч допускает потерю изменений после последней допустимой копии |
| RTO | Максимально допустимое время восстановления заданной работоспособности после объявленного сбоя |
| MVP | Первая полезная сквозная поставка для выбранной цели. В проекте — проведение матча до официальной статистики и табло |
| Релиз | Накопительная поставка возможностей; история размещена в USM там, где впервые появляется |

## 6. Согласованные состояния

| Объект | Состояния и смысл |
|---|---|
| Матч | Planned → InProgress → Finished; из Planned возможен Cancelled. Подтверждение результата учитывается отдельно |
| Состав матча | Submitted → Confirmed либо NeedsCorrection → новая Submitted-версия |
| Результат матча | Ожидает проверки → Confirmed; при возврате NeedsCorrection. После опубликованного результата разрешён UnderCorrection |
| Протокол | Предварительные/итоговые редакции; публикация конкретной подтверждённой редакции даёт Published |
| Отчёт, инфографика, прогноз | Draft → Ready → Published. Для прогноза возможен Rejected с причиной вместо Ready |
| Обработка отчёта/видео | Текущая попытка → Failed; разрешённый повтор создаёт новую Queued-попытку у того же объекта |
| Видео | Uploaded → Ready; ошибка и очередь относятся к обработке, не уничтожают исходный файл |
| Импорт | Received → Validated либо Conflict; исправление сопоставления требует новой проверки перед применением |
| Сезон | Open → Closed. Архив и восстановленная копия — связанные объекты, а не автоматическое повторное открытие сезона |

Названия состояний здесь задают смысл переходов, а не окончательный перечень колонок и классов. Нельзя одним полем «всё готово» подменять завершение матча, подтверждение результата и публикацию.

## 7. Неоднозначные слова

- Вместо «состав» уточнять: **сезонная заявка команды** или **состав матча**.
- Вместо «матч подтверждён» уточнять: **подтверждена редакция результата**.
- Вместо «письмо доставлено» при одном ответе SMTP писать: **письмо передано почтовому сервису**.
- Вместо «инфографика запрошена» при создании объекта писать: **черновик инфографики создан**.
- Вместо «пользователь получил роль» уточнять **роль и область назначения**.
- Вместо «всё в реальном времени» указывать измеримую задержку и условия, например PER03.
- Вместо «сохранить историю» различать **аудит**, **архив** и **резервную копию**.
